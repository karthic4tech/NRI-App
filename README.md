# NRI Services Web App

Angular 21 standalone application for NRI Services, deployed to Cloudflare Workers and authenticated with Supabase Auth.

## Project setup

- Frontend: Angular 21
- Auth: Supabase Auth with Google OAuth
- Hosting: Cloudflare Workers
- Production URL: `https://nri-app.imayamoverseas.workers.dev`

## Supabase configuration

Set these values in the Angular environment files:

- `supabaseUrl` — your Supabase project URL, for example `https://your-project.supabase.co`
- `supabasePublishableKey` — the publishable / anon key
- `siteUrl` — the application base URL used for OAuth redirects

Do **not** place any of the following in frontend code:

- Supabase service-role key
- Google OAuth client secret

## Google Cloud OAuth setup

1. Open the Google Cloud Console.
2. Create or select an OAuth 2.0 client.
3. Add your Supabase OAuth callback domain as an authorized redirect URI.
4. Use the Google client ID in Supabase Auth, not in the Angular app.
5. Keep the Google client secret only inside Google Cloud and Supabase.

## Supabase redirect URL configuration

In the Supabase dashboard:

- Enable Google as an auth provider.
- Set the redirect URL(s) to the app callback route:
  - Production: `https://nri-app.imayamoverseas.workers.dev/auth/callback`
  - Local development: `http://localhost:4200/auth/callback`
- Add any other preview or staging URLs you plan to use.

The app uses `/auth/callback` to finish the OAuth flow and restore the session after refresh.

## Free consultation submissions

Suggested Supabase table name: `consultation_requests`

Create a table like this in Supabase SQL Editor:

```sql
create table if not exists public.consultation_requests (
  id bigint generated by default as identity primary key,
  name text not null,
  phone_number text not null,
  city text not null,
  country text not null,
  created_at timestamptz not null default now()
);

alter table public.consultation_requests enable row level security;

create policy "Allow public consultation inserts"
on public.consultation_requests
for insert
to anon, authenticated
with check (true);
```

If you want only logged-in users to submit requests, remove `anon` from the policy and require login before submission.

## Task creation for logged-in users

The task flow now expects the caller to be authenticated and uses the logged-in user's JWT when calling the Supabase Edge Function.

### Recommended task table structure

If you want each task to belong to the logged-in user, use this schema:

```sql
create table public.tasks (
  "TaskIdentity" bigint generated always as identity not null,
  "TaskId" character varying(20) not null default (
    'NRI-TSK-'::text || upper(
      substring(replace((gen_random_uuid())::text, '-', '') from 1 for 8)
    )
  ),
  "UserId" uuid not null references auth.users(id) on delete cascade,
  "UserEmail" text not null,
  "Name" character varying(200) not null,
  "TaskTitle" character varying(300) not null,
  "ServiceDescription" character varying(1000) not null,
  "CreatedAt" timestamp with time zone not null default now(),
  "UpdatedAt" timestamp with time zone not null default now(),
  constraint tasks_pkey primary key ("TaskIdentity"),
  constraint "tasks_TaskId_key" unique ("TaskId"),
  constraint tasks_description_not_empty check (length(trim(both from "ServiceDescription")) > 0),
  constraint tasks_name_not_empty check (length(trim(both from "Name")) > 0),
  constraint tasks_title_not_empty check (length(trim(both from "TaskTitle")) > 0)
);

create unique index if not exists ux_tasks_task_id on public.tasks using btree ("TaskId");
create index if not exists ix_tasks_user_id on public.tasks using btree ("UserId");
```

### Optional RLS policies

If you later decide to query `tasks` directly from the frontend, add RLS policies like these:

```sql
alter table public.tasks enable row level security;

create policy "Users can read their tasks"
on public.tasks
for select
using (auth.uid() = "UserId");

create policy "Users can create their tasks"
on public.tasks
for insert
with check (auth.uid() = "UserId");
```

### Edge function behavior

The `create-task` edge function should:

- read the `Authorization: Bearer <access_token>` header
- verify the logged-in Supabase user
- insert `UserId` and `UserEmail` with the task
- return only tasks owned by that user when listing or searching

That keeps each user's task data separated even when the function runs with a service-role key.

## Local development

```bash
npm install
npm start
```

The app runs at `http://localhost:4200/` by default.

## Production build and local verification

```bash
npm run build
npm run test
```

For a local production-style preview, serve the generated `dist/` output using your preferred static server or the Cloudflare Wrangler preview flow.

## Cloudflare deployment

The repository uses `wrangler.jsonc` to point at the Angular build output:

- `dist/nri-customer-web-app/browser`

Typical deploy flow:

```bash
npm run build
npx wrangler deploy
```

If you use Cloudflare Pages or a different pipeline, keep the SPA fallback behavior enabled for client-side routes.

## Notes

- Public pages remain public.
- Protected routes redirect unauthenticated users to `/login` and preserve the intended destination.
- Authentication state is restored on browser refresh through Supabase session recovery.
